# Liuyao Minimal Judgment Loop Design

## Goal

Extend the current Liuyao chart MVP into a minimal judgment loop.

The loop should still be conservative: it produces structured intermediate evidence and a prompt-controlled reasoning frame, not a full traditional Liuyao final judgment engine. The model should receive enough Liuyao-native structure to reason in order:

1. Identify the question domain.
2. Locate candidate useful gods on concrete lines.
3. Check shi/ying.
4. Check month and day effects.
5. Check moving and changed-line effects.
6. Synthesize a cautious tendency with uncertainty.

## Hard Boundary

This feature remains Liuyao-only.

Allowed shared dependency:

- `dongxuan_agent.calendar_engine` for ganzhi calendar fields, month branch, day branch, and xunkong.

Forbidden:

- Bazi day-master strength, ten-god strength, pattern, climate, remedy, luck, discipline, or imagery systems.
- Daliuren four lessons, transmissions, heavenly officers, or Daliuren spirit-sha hit logic.
- Treating Wang/Xiang/Xiu/Qiu/Si as Bazi strength.

The Liuyao strength model must be branch/element based:

- Line branch and element from najia.
- Month branch and month element.
- Day branch and day element.
- Six-relative and role from Liuyao chart data.
- Moving and changed-line effects from the hexagram.

## Non-Goals

This stage does not implement:

- Full final auspicious/inauspicious judgment.
- Numeric scoring as a public contract.
- Six spirits.
- Spirit-sha.

- Three-combination bureau judgment.
- Advance/retreat spirit.

- Event timing.
- Multi-school variants.
- Time-based hexagram generation.

## Five-Element Seasonal Strength

Add a Liuyao-native seasonal strength layer.

### Month Element

Derive month element from `calendar.month_branch`:

```json
{
  "子": "水",
  "丑": "土",
  "寅": "木",
  "卯": "木",
  "辰": "土",
  "巳": "火",
  "午": "火",
  "未": "土",
  "申": "金",
  "酉": "金",
  "戌": "土",
  "亥": "水"
}
```

### Wang/Xiang/Xiu/Qiu/Si Rules

For each line element, compare it to the month element:

- `旺`: line element equals month element.
- `相`: line element is generated by month element.
- `休`: line element generates month element.
- `囚`: line element controls month element.
- `死`: month element controls line element.

Example in `巳` month:

- 火: `旺`
- 土: `相`
- 木: `休`
- 水: `囚`
- 金: `死`

This is a categorical strength state, not a final judgment.

### Effective Strength

Add `effective_strength` as a coarse label:

- `very_strong`
- `strong`
- `balanced`
- `weak`
- `very_weak`

Use this as internal reasoning support and JSON evidence. It should be derived from:

- seasonal state
- whether month branch directly equals, generates, controls, clashes, or combines the line branch
- whether day branch directly equals, generates, controls, clashes, or combines the line branch
- moving status
- changed-line return relation
- xunkong

Do not expose a numeric score as the stable API. Implementation can use internal weights, but JSON must expose labels and evidence strings.

### Extreme State

Add `extreme_state`:

- `over_strong`
- `over_weak`
- `none`

`over_strong` should require at least:

- seasonal state is `旺` or `相`
- and at least two additional support factors, such as day support, same branch, active moving line, or changed-line return generation
- and no major weakening factor such as xunkong or month/day clash

`over_weak` should require at least:

- seasonal state is `囚` or `死`
- and at least two weakening factors, such as day control, clash, xunkong, changed-line return control, or being controlled by a moving line
- and no meaningful support factor

These labels must be conservative. If evidence is mixed, use `none`.

## Branch And Element Relations

Add a small Liuyao relation engine.

### Element Relation Values

For subject A acting on target B:

- `same`
- `generates`
- `controls`
- `generated_by`
- `controlled_by`
- `drains_to`
- `drained_by`
- `none`

Use clear direction in JSON:

```json
{
  "actor": "day",
  "target_position": 3,
  "relation": "generates",
  "meaning": "日辰五行生本爻"
}
```

### Branch Relation Values

Implement only:

- `same`
- `clash`
- `combine`
- `none`
- `not_evaluated`

Do not implement harm, punishment, tomb, absolute, three-combination, or hidden branch logic in this stage.

## Prompt Upgrade

Update `liuyao_prompt.md` from a chart-summary prompt to a minimal-loop prompt.

The prompt must require:

- Use `derived_lines` as the primary line evidence.
- Use `useful_god_analysis` to locate useful-god candidates.
- Use `relations.month_day` for month/day effects.
- Use `relations.shi_ying` for shi/ying.
- Use `relations.moving_effects` for moving and changed-line effects.
- Always mention `extreme_state` when it is `over_strong` or `over_weak`.
- Do not treat `旺` as automatically good or `死` as automatically bad.
- Do not turn candidate useful gods into final useful gods unless the evidence supports that within implemented fields.
- Do not invent six spirits, hidden spirits, flying spirits, three-combination, tomb/absolute, or timing.

The prompt output format should be:

```markdown
## 卦体摘要

## 用神定位

## 世应关系

## 旺衰与月日

## 动变作用

## 综合倾向

## 不确定项
```

`综合倾向` must use cautious labels:

- `偏有利`
- `偏不利`
- `反复/未定`
- `证据不足`

It must include evidence bullets and uncertainty bullets.

- Missing useful-god candidates are listed without fabricating hidden spirits.
- Shi/ying relation is generated from existing line elements and branches.
- Moving-line relation targets shi, ying, and useful-god lines.
- Changed-line return relation labels `回头生` and `回头克` are generated.
- `over_strong` requires multiple support factors and no major weakening factor.
- `over_weak` requires multiple weakening factors and no meaningful support factor.
- Prompt includes the fixed seven output sections.
- Liuyao v2 JSON does not include forbidden Bazi or Daliuren fields.
